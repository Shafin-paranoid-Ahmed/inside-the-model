  SPEC: two character n-gram language models built from a small public-domain corpus bundled as a short string: target p = trigram, draft q = bigram (both add-k smoothed). Costs are counted (bytes moved, model calls), never milliseconds.

(a) TEXTBOOK-STABLE MECHANISMS:
- Decoding one token reads every weight once; at small batch the bound is memory bandwidth, so fewer bytes per weight means faster tokens.
- Symmetric absmax quantization: scale = max|w| / (2^(b-1) - 1), q = round(w / scale); error up to scale/2; one outlier inflates the scale for all weights in its group; per-channel / group-wise scales fix this.
- Speculative sampling: accept draft token x with probability min(1, p(x)/q(x)); on rejection sample from normalise(max(0, p - q)); the output distribution equals p exactly.
- Acceptance rate alpha = sum_x min(p(x), q(x)); expected tokens per target call with gamma drafts = (1 - alpha^(gamma+1)) / (1 - alpha) (i.i.d. approximation from Leviathan et al.).
- Distillation: minimise T^2 * KL(softmax(z_t/T) || softmax(z_s/T)) plus the hard-label loss.

(b) RESEARCH LIST:
R1 Speculative decoding: Leviathan et al. arXiv 2211.17192 and Chen et al. arXiv 2302.01318 (both confirmed 2026-10-03): exact rule, proof, speedup formula and reported conditions.

*/}

<Step title="Why serving is slow: moving weights, not doing maths">

When a model writes one token at a time, most of the time goes into reading its weights from memory, not into the arithmetic.

<Step title="Quantization: fewer bits per weight">

Quantization rounds each weight to one of a small number of levels, so it can be stored in fewer bits, and the rounding error decides how much quality is lost.

{/*
IDEA: absmax rounding; error grows as bits fall.
WIDGET: InferenceLab mode="quantize" grouping="tensor". The 16x16 weight matrix as a heat grid (--viz-pos/--viz-neg), its histogram with the quantization levels as ticks, rounding arrows; readouts: bits, mean squared error, network accuracy.
T: t sweeps bits from 8 down to 2; the level ticks spread apart, weights snap to them, accuracy updates.
TRY: pause at 4 bits and at 3 bits and compare the accuracy.
QUOTE: weight MSE and accuracy at 8, 4, 3, 2 bits (per-tensor).
MATH: scale, round, clamp; max error scale/2. CODE: 5-line numpy quantize/dequantize.
RESEARCH: R2 (one sentence on what real methods add, e.g. GPTQ's error compensation).
*/}

</Step>

<Step title="Outliers and smaller groups">

A single very large weight stretches the scale for everything that shares it, so practical schemes give each row or small group of weights its own scale.

{/*
IDEA: outlier sensitivity; per-channel and group-wise scales.
WIDGET: InferenceLab mode="outliers" bits=4 outlier=true (buttons grouping tensor / row / group-8). Same grid with one weight multiplied by 20; histogram shows most weights collapsed onto the zero level under per-tensor scaling.
T: t animates the scale shrinking as grouping goes tensor -> row -> group of 8; weights re-snap.
TRY: switch from tensor to group-8 and compare how many weights round to zero.
QUOTE: weights rounded to zero and accuracy for each grouping at 4 bits with the outlier; extra bits per weight spent on scales.
MATH: overhead = scale bits / group size.
RESEARCH: R2 (LLM.int8 outlier finding, AWQ activation-aware scaling: quote their statements).
*/}

</Step>

<Step title="Speculative decoding: draft, then verify">

A small fast model guesses several tokens ahead, and the large model checks all the guesses at once, keeping the ones it agrees with.

{/*
IDEA: draft gamma tokens with q, score them with p in one target call, accept/reject left to right.
WIDGET: InferenceLab mode="speculate" gamma=4. T: t plays 20 rounds of real seeded speculative sampling; phases Draft / Check / Accept or resample.
TRY: pause on a rejection and compare u with p/q for that token.
QUOTE: tokens per target call over the 20 rounds; acceptance rate measured vs alpha computed.
MATH: the acceptance rule. CODE: 12-line numpy speculative sampling step.

<Step title="The acceptance rule keeps the large model's answers">

The accept-or-resample rule is designed so that the text produced has exactly the same probabilities as if the large model had written it alone.

{/*
IDEA: exactness proof made visible.
WIDGET: InferenceLab mode="exact" context="th". For one fixed context: three histograms over next characters: target p, draft q, and the empirical distribution of speculative outputs.
T: t runs 1 to 20000 seeded trials (log); the empirical histogram converges onto p, not q.
TRY: watch the bar for the character where p and q differ most.
QUOTE: total variation distance between empirical and p, and between q and p, at 20000 trials; alpha for this context.
MATH: Show the math: P(output = x) = q(x) min(1, p/q) + (1 - alpha) * max(0, p - q)/(1 - alpha) = p(x).
RESEARCH: R1 (proof as stated in the papers).
*/}

</Step>

<Step title="Distillation: a small model learns from a large one">

A small student model can learn more from a large teacher's full probability outputs than from the right answers alone, because the probabilities show which mistakes are close.

{/*
IDEA: soft targets carry information about similarity between classes ("dark knowledge"); temperature softens them.

T: t = training epoch (precomputed in a worker); both student boundaries evolve; curves draw.
TRY: set T = 1 and compare the soft-target student's final accuracy with T = 4.
QUOTE: final test accuracy of teacher, hard-label student and distilled student at T = 1 and T = 4.
MATH: the distillation loss with the T^2 factor. CODE: PyTorch loss line.

<Step title="Common misconceptions">

A few common beliefs about efficient inference are wrong.

{/*
NO WIDGET. Misconceptions:
1. Speculative decoding changes the output quality. With the exact rule, it does not (step 5, R1).
2. Quantization error is spread evenly. Outliers dominate (step 3, R2).
3. Distillation just copies the teacher's answers. Soft targets carry more (step 7, R3).
4. Faster arithmetic always means faster decoding. Small-batch decoding is memory-bound (step 1).
*/}

</Step>

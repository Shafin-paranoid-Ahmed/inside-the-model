(a) TEXTBOOK-STABLE MECHANISMS:
- Attention scores form an L x L matrix: compute and (naive) memory grow as L^2; FlashAttention removes the L^2 memory but not the L^2 compute.
- KV cache bytes = 2 x layers x kv_heads x head_dim x L x bytes_per_value; grouped-query attention shrinks kv_heads.
- RoPE rotates each 2D pair of q/k dims by angle m * theta_i, theta_i = base^(-2i/d); low-frequency pairs never complete a turn in training, so longer positions give unseen angles.
- Position interpolation divides positions by s; NTK-aware scaling raises the base; YaRN scales frequencies by band and adds an attention temperature.
- Sliding-window attention costs L x w; stacked layers widen the reach to about layers x w; keeping a few initial "sink" tokens stabilises windowed attention.
- Sparse patterns (local + global + random) cut the number of scored pairs.
- Needle-in-a-haystack tests retrieval only; harder tests add multi-hop and aggregation.

<Step title="Every token looks at every other token">

In attention, each new token is compared with every token before it, so the number of comparisons grows with the square of the input length.

{/*
IDEA: quadratic attention cost. Link /learn/transformers/self-attention/.
WIDGET: LongContextLab mode="quadratic". A triangular causal score matrix drawn as a grid that zooms out as L grows; log-log readout of scored pairs and FLOPs vs L.
T: t sweeps L from 1e2 to 1e6 (log); the grid zooms, the counter climbs.
TRY: compare the pair count at 1e4 and 1e5: ten times the length, about a hundred times the work.
QUOTE: scored pairs at L = 1e3, 1e4, 1e5, 1e6 (L(L+1)/2).
MATH: pairs = L(L+1)/2; FLOPs about 4 L^2 d per layer.
RESEARCH: R6 (one sentence: FlashAttention fixes memory traffic, not the count).
*/}

</Step>

<Step title="The KV cache grows with every token">

During generation the model stores a key and a value for every past token in every layer, and for long inputs that cache can outgrow the model's own weights.

{/*
IDEA: KV-cache memory. Link /learn/llms/inference-kv-cache/.
WIDGET: LongContextLab mode="kvcache" kvHeads=8 (sliders: KV heads 1 to 32, bytes 1/2/4). Stacked bar: weights vs KV cache for a labelled hypothetical config; L on a log axis.
T: t sweeps L from 1e3 to 1e6; the cache bar overtakes the weight bar.
TRY: move KV heads from 32 to 8 (grouped-query attention) and find the new crossover length.
QUOTE: cache bytes at L = 1e5 for kvHeads = 32 and 8 under the stated config; the crossover L.
MATH: the KV formula.
RESEARCH: GQA paper Ainslie et al. arXiv 2305.13245 (VERIFY).
*/}

</Step>

<Step title="Positions the model never saw">

Rotary position encodings turn each pair of dimensions by an angle that grows with position, and past the training length the slow-turning pairs reach angles the model has never seen.

{/*
IDEA: RoPE extrapolation failure. Link /learn/transformers/positional-encodings/.
WIDGET: LongContextLab mode="extrapolate" trainLen=64. Left: one dial per frequency pair, the arc covered during training shaded, the current position's angle as a needle (outside the arc = --viz-neg). Right: the tiny model's retrieval accuracy vs test length 32 to 512.
T: t moves the position from 0 to 512; fast dials spin many turns (always in range), slow dials leave their shaded arc after 64.
TRY: watch the slowest dial leave its shaded arc, and the accuracy curve drop at the same length.
QUOTE: accuracy at 64, 128, 256 with no scaling; the lowest pair's trained arc in degrees.
MATH: theta_i = base^(-2i/d); angle = m theta_i.
RESEARCH: R1.
*/}

</Step>

<Step title="Stretching the positions: interpolation and frequency scaling">

Context-extension methods rescale the rotation angles so that long inputs map back into the range of angles seen in training, at the cost of finer position detail.

{/*
IDEA: position interpolation vs NTK-aware base scaling vs YaRN band-wise scaling, each with a short fine-tune of the tiny model at length 256.
WIDGET: LongContextLab mode="interpolate" method="pi" (buttons pi / ntk / yarn; default pi). Same dials as step 3 with the rescaled arcs; accuracy vs length for the chosen method beside the unscaled curve.
T: t sweeps test length 32 to 1024; curves draw; dials show the rescaled angles.
TRY: switch from pi to yarn and compare accuracy at 1024 and at short lengths.
QUOTE: accuracy at 64 and 1024 for none / pi / ntk / yarn after the same fine-tune budget.
MATH: PI: m -> m/s; NTK: base -> base * s^(d/(d-2)); YaRN ramp (from R2).
RESEARCH: R2, R3.
*/}

</Step>

<Step title="Look nearby: sliding-window attention">

Sliding-window attention lets each token attend only to the last few hundred tokens, which makes cost grow linearly, and stacking layers lets information travel further.

{/*
IDEA: windowed attention, reach = layers x window, attention sinks.
WIDGET: LongContextLab mode="window" window=8 layers=4 sinks=0 (toggle sinks=4). Mask matrix with the band; a token's reach cone grows layer by layer; cost readout L x w.
T: t plays the reach growing layer by layer for one query token, then L sweeping.
TRY: turn on 4 sink tokens and see the first column of the mask light up.
QUOTE: scored pairs for L = 1e4, w = 512 vs full attention; reach after 4 layers.
MATH: pairs about L w.
RESEARCH: R4 (StreamingLLM's sink finding, cited with its conditions).
*/}

</Step>

<Step title="Sparse patterns: local plus global">

Other designs mix a local window with a few global tokens that see and are seen by everything, keeping cost low while any two tokens stay a couple of hops apart.

{/*
IDEA: Longformer/BigBird-style sparse attention.
WIDGET: LongContextLab mode="sparse" window=4 global=2 random=2. Mask matrix showing the three pattern parts in distinct --viz-seq shades; readouts: nonzeros vs dense, maximum hops between two tokens.
T: t builds the mask pattern part by part (window, then global rows/columns, then random), then sweeps L.
TRY: remove the global tokens and watch the hop count jump.
QUOTE: nonzero fraction at L = 64 and 4096; hops with and without globals.
MATH: count of nonzeros.
RESEARCH: R4.
*/}

</Step>

<Step title="Measuring use: a needle in a haystack">

To test whether a model actually uses a long input, hide one fact somewhere in filler text and ask for it, at many lengths and depths.

<Step title="Common misconceptions">

Long context is often misunderstood in a few predictable ways.

{/*
NO WIDGET. Misconceptions:
1. A model with a 1M-token window uses all of it equally well (R5).
2. FlashAttention makes attention linear (R6: it is exact attention with less memory traffic).
3. Position interpolation is free (step 4: short-range resolution drops; needs fine-tuning, R2).
4. Retrieval success means reasoning over the whole context (step 7 multi-hop).
*/}

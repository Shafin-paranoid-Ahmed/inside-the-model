<Step title="Text becomes a vector">

An embedding model turns a piece of text into a list of numbers, so that texts about the same thing get similar lists.

{/*
IDEA: embedding = function text -> fixed-length vector (here 16 numbers). Ours is LSA (TF-IDF matrix + truncated SVD, Deerwester et al. 1990), a real, classic embedding method computed in closed form from the corpus; production systems use a trained transformer encoder (link /learn/transformers/embeddings/). Say this once, plainly.
WIDGET: EmbedSearch mode="embed" query="overdue fees". Left: the 40 handbook passages as points in a 2D PCA projection of their 16-D vectors, coloured by --viz-seq intensity of similarity to the query. Right: the query's 16 numbers as a bar strip (--viz-pos / --viz-neg).
MOTION over t: the query's words are looked up one by one (TF-IDF weights appear), the 16-D vector assembles bar by bar, then the query point flies from the centre to its place in the projection and its 3 nearest passages get connecting lines.
TRY: hover a point to read its passage; passages about fees cluster.
QUOTE: dimension (16), number of passages, vocabulary size, and the share of variance the 2D picture keeps (so the reader knows the projection loses information).
SHOW THE MATH: TF-IDF weight, truncated SVD X ≈ U_k S_k V_k^T, query fold-in q_k = S_k^-1 U_k^T q.
SHOW THE CODE: sklearn TfidfVectorizer + TruncatedSVD(16) in 8 lines, matching the sim.
*/}

<Step title="Measuring similarity: cosine and dot product">

Two vectors are similar when they point the same way; cosine similarity measures the angle and ignores length, while the dot product also rewards length.

{/*
IDEA: cosine = dot of unit vectors; dot product favours long vectors (long passages / frequent words); after normalising, both rank identically and the dot is cheaper. Link /learn/math/dot-product/.
WIDGET: EmbedSearch mode="similarity" query="overdue fees". Top-8 list with two score columns, cosine and raw dot, plus the vector length of each passage.
MOTION over t: a toggle-like sweep over t: first ranked by dot, then the bars glide to their cosine order; then all vectors are normalised (lengths animate to 1) and the dot ranking collapses onto the cosine ranking.
TRY: find the long passage that the dot product over-ranks.
QUOTE: that passage's rank under dot vs cosine, its length; confirm ranks identical after normalisation.
REUSE NOTE: DotProduct mode="geometry" already teaches the angle picture; do not repeat it, link to it.
SHOW THE MATH: cos(a,b) = a·b / (|a||b|).
*/}

</Step>

<Step title="Exact search: compare against everything">

The simplest search computes the similarity between the query and every stored vector and keeps the best few.

{/*
IDEA: brute-force k-NN is exact, cost grows linearly with N (N·d multiply-adds per query). Fine for 40 passages, not for a billion.
WIDGET: AnnIndex mode="exact" k=5. 2D synthetic set (seeded clustered points, 2000 points) drawn on Canvas; a query point.
MOTION over t: a scan line sweeps the points in storage order, each visited point flashes, the running top-5 list updates; a counter counts distance computations to 2000.
TRY: drag the query point; the scan replays.
QUOTE: comparisons = N; then the cost at N = 1e9, d = 768 computed in the readout (multiply-adds), as a scale bar on a log axis.
SHOW THE CODE: numpy argpartition top-k over a matrix product.
*/}

</Step>

<Step title="IVF: search only the nearest buckets">

An inverted-file index groups the vectors into clusters ahead of time, then searches only the few clusters nearest the query.

{/*
IDEA: IVF = k-means into nlist cells (reuse KMeansLab kmeans + initCentroids 'plusplus'), each vector stored in its cell's list; a query compares to the nlist centroids, then scans the nprobe nearest lists. Misses happen when a true neighbour sits just across a cell border.
WIDGET: AnnIndex mode="ivf" nlist=16 nprobe=1. Same 2000 points, cells drawn as Voronoi regions (thin lines, cell fill = --viz-seq-1).
MOTION over t: centroids compared (16 flashes), the nearest cell fills, its points are scanned, the found top-5 appear; then the true top-5 are ringed so a missed neighbour (if any) is visible across the border.
TRY: raise nprobe from 1 to 4 (slider) and watch recall and comparisons both rise.
QUOTE: recall@5 and comparisons for nprobe = 1, 2, 4 at this query, and averaged over 200 seeded queries.
*/}

</Step>

<Step title="HNSW: a graph you can walk downhill">

HNSW links each vector to a few close neighbours in a layered graph, and a search hops greedily from neighbour to neighbour toward the query.

{/*
IDEA: hierarchical navigable small world (Malkov & Yashunin): few nodes on upper layers with long links, all nodes on layer 0; greedy descent per layer, then a beam of width ef on layer 0. Levels drawn from a seeded geometric distribution.
WIDGET: AnnIndex mode="hnsw" M=6 ef=8. Same points (subsample 400 for a readable graph). Layers drawn as stacked translucent planes? NO: draw only the current layer's edges in 2D, layer number in the readout, to stay readable at 390 px.
MOTION over t: entry point on top layer, greedy hops (particle along each edge, --viz-forward), drop to next layer, repeat, then the layer-0 beam expands; visited nodes counted.
TRY: drag the query; raise ef from 8 to 32.
QUOTE: hops per layer, visited nodes, recall@5 for ef = 8 and 32 (from sim).
SHOW THE MATH: none; Show the code: faiss IndexHNSWFlat(d, 32) three lines, marked as the real library call.
*/}

</Step>

<Step title="The speed and recall trade-off">

Approximate indexes trade a little accuracy, measured as recall, for a large saving in comparisons.

<Step title="Common misconceptions">

A few ideas about embeddings and search that are easy to get wrong.

{/*
NO WIDGET. Intended misconceptions:
1. "Embeddings understand meaning." They encode co-occurrence statistics; similar vectors mean similar usage in training text, which can include unwanted associations.
2. "Cosine similarity of 0.8 means 80% relevant." Scores are only comparable within one model; the scale differs between models.
3. "Approximate search returns wrong answers." It sometimes misses a true neighbour; recall is measured and tunable.
4. "More dimensions are always better." Cost and memory grow with d; distances concentrate in high dimensions (link classic-ml/k-nearest-neighbors).
5. "Vector search replaces keyword search." Exact strings (ids, names, codes) favour keyword search; many systems combine both (hybrid).
*/}

</Step>

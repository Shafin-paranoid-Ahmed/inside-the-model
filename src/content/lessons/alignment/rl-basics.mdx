Instead of labeled answers, the learner gets only a score for what it did.

<Step title="An agent, an environment and a score">

Imagine learning a video game with no manual and no teacher. You press buttons, the screen changes, and a score ticks up or down. Nobody ever tells you "that was the right button". **Reinforcement learning** (RL) studies exactly this situation. The learner is the **agent**. The world it acts in is the **environment**. At each moment the environment is in some **state** (where the agent is), the agent picks an **action**, and the environment answers with a new state and a number called the **reward**. One run from the start until the game ends is an **episode**.

This is different from the supervised learning of the first days, where every example came with the right answer. Here the only feedback is a score, and it may arrive long after the move that earned it.

Our environment is a small grid, the classic 4 by 3 world from Russell and Norvig's textbook. The agent starts at the bottom left, a grey wall blocks one cell, the top-right cell is a +1 goal and the cell below it is a −1 pit. Both end the episode. Every move costs 0.04, so wandering is mildly punished. Moves are also slippery: 80% of the time the agent goes where it asked, and 20% of the time it veers sideways. Here the agent has no idea what it is doing and picks every action at random.

<GridWorldLab client:visible mode="loop" seed={34} title="One episode of a random agent" />

Watch the first move. The agent asked for one direction, the dashed arrow, and the world moved it another way, the solid arrow. That was a slip on move 1. This episode lasts 15 moves and ends in the +1 goal with a total reward of +0.40, which is lucky: most random episodes end in the pit. Learning means turning episodes like this one into a better way of choosing actions.

</Step>

<Step title="A Markov decision process">

To reason about the grid we write its rules down exactly. A **Markov decision process** (MDP) is a list of the states, the actions, the probability of each next state given the current state and action, and the reward. The word *Markov* means that the next state depends only on the present state and the action taken, not on how the agent got there. The present state is all you need to remember.

In the figure, the highlighted cell is (3,1): third column, bottom row. The timeline asks for each of the four actions in turn. The arrows show where the move can end up, with width proportional to its chance. Then the world is asked 20 times, and each try drops into the cell it landed in.

<GridWorldLab client:visible mode="mdp" focus="3,1" seed={5} title="Where one move can end up from (3,1)" />

Look at **down**. There is nothing below the bottom row, so the intended move bumps the edge and the agent stays put, with chance 0.8. In the 20 tries, 16 stayed put, 2 went left to (2,1) and 2 went right to (4,1). The exact chances are 0.8, 0.1 and 0.1, and with only 20 tries the counts are close to, but rarely equal to, the exact numbers: **left** gave 12 of 20 where 16 would be expected. Use the menu to pick another cell, such as (2,1) next to the wall.

<details>
<summary>Show the math</summary>

The environment is the tuple $(S, A, P, R, \gamma)$ of states, actions, transition probabilities, rewards and a discount factor (met in two steps). The transition probability and the Markov property are

$$P(s' \mid s, a) = \Pr(S_{t+1} = s' \mid S_t = s, A_t = a), \qquad \Pr(S_{t+1} \mid S_t, A_t, S_{t-1}, A_{t-1}, \dots) = P(\cdot \mid S_t, A_t).$$

For up at (3,1): $P((3,2) \mid (3,1), \text{up}) = 0.8$ and each sideways cell gets 0.1. The reward $R(s, a, s')$ is $-0.04$ for every move, plus $+1$ or $-1$ when the move enters the goal or the pit.

</details>

</Step>

<Step title="Policies and returns">

A **policy** is the agent's rule for choosing an action in each state. The arrows in the figure are a policy: in every cell, go that way. The **return** is the total reward the agent collects from some moment on. Rewards that come later are shrunk by a **discount factor** $\gamma$ between 0 and 1: a reward $k$ moves away counts $\gamma^k$ times as much. This says "a point now is worth more than a point later" and keeps the sum finite in long tasks.

Returns are easiest to find backward. The last move's return is just its reward. Every earlier return is that move's reward plus $\gamma$ times the return of the move after it. In the figure the agent first walks one episode under a good policy, then the table fills in from the bottom.

<GridWorldLab client:visible mode="return" seed={3} gamma={0.9} title="Returns, found from the end of the episode" />

This episode has 5 moves and no slips. The rewards are −0.04 four times and then +0.96 for the final move into the goal (+1 minus the 0.04 cost). Their plain sum is 0.80. With $\gamma = 0.9$ the return from the start is only 0.492, because the +0.96 sits four moves away and counts $0.9^4$ of its size. Choose "1 (none)" in the menu and the two numbers become equal.

<details>
<summary>Show the math</summary>

$$G_t = r_{t+1} + \gamma r_{t+2} + \gamma^2 r_{t+3} + \dots = \sum_{k=0}^{\infty} \gamma^k r_{t+k+1}, \qquad G_t = r_{t+1} + \gamma\, G_{t+1}.$$

Check with the last move: $G_4 = 0.96$. Then $G_3 = -0.04 + 0.9 \cdot 0.96 = 0.824$, and so on down to $G_0 = 0.492$.

</details>

</Step>

<Step title="What the discount factor decides">

The discount factor sets how much the agent cares about the future. Near 0 it is short-sighted; near 1 it is patient. Because the grid is slippery, that can change which move is best. For each $\gamma$ the figure solves the grid exactly (with value iteration, met in the next step) and draws the best move in every cell. The left grid stays at $\gamma = 0.5$. The right grid sweeps $\gamma$ up to 0.99, and any arrow that differs from the left grid turns to the accent colour.

<GridWorldLab client:visible mode="discount" gammas="0.5,0.99" title="Best moves at γ = 0.5 and as γ grows" />

Two arrows flip. At $\gamma = 0.660$ the cell below the pit, (4,1), changes from down to left. A short-sighted agent there prefers to stay safely in the corner: the goal is so far away that walking back is not worth the 10% risk of slipping into the pit. A patient agent walks away. At $\gamma = 0.938$ the cell (2,1) changes from right to left: it takes the long way around the wall instead of the short route past the pit. The route from the start never changes, so these flips matter only after a slip pushes the agent off it. What changes a lot is the start cell's value: −0.05 at $\gamma = 0.5$ and 0.66 at $\gamma = 0.99$, because the far-off goal counts almost nothing to the first agent and nearly in full to the second.

</Step>

<Step title="Value functions">

The **value** of a state is the return the agent can expect from there if it keeps following its policy, averaged over all the ways the slippery moves can turn out. We write it $V(s)$. Unlike the return of a single episode, value is an average, so it does not depend on a lucky or unlucky seed.

The MDP is fully known here, so there is nothing to learn yet: we can compute values by **policy evaluation**. Start with every value at 0. Then repeat a sweep: set each cell's value to the chance-weighted average, over the possible outcomes of its move, of the reward plus the old value of the cell the move lands in. The panel on the right spells out this sum for one cell, the start. (Here $\gamma = 1$ and the policy is the best one for the grid.)

<GridWorldLab client:visible mode="value" gamma={1} stepReward={-0.04} title="Policy evaluation, sweep by sweep" />

Watch the start cell. For the first four sweeps it only gets worse, −0.04, −0.08, −0.12, −0.16, because the goal is more than that many moves away and each sweep only adds one more move's cost. Sweep 5 is the first to carry news of the goal and the value jumps to 0.128. After that it climbs, 0.326, 0.482, 0.579, and settles. By sweep 13 it is within 0.005 of its final value, 0.705, which agrees with the utilities printed in the [textbook](http://aima.cs.berkeley.edu/).

A closely related quantity is $Q(s, a)$, the value of taking action $a$ first and following the policy afterwards. It lets an agent compare actions directly, and the [next lesson](/learn/alignment/q-learning/) learns it from experience.

<details>
<summary>Show the math</summary>

$$V^\pi(s) = \sum_a \pi(a \mid s) \sum_{s'} P(s' \mid s, a)\,\bigl[r(s, a, s') + \gamma\, V^\pi(s')\bigr].$$

This is the Bellman expectation equation. Policy evaluation turns it into an update, repeated until the values stop changing.

</details>

<details>
<summary>Show the code</summary>

```python
import numpy as np

def policy_evaluation(P, R, pi, gamma, sweeps):
    # P[s, a, s2] transition probabilities, R[s, a, s2] rewards, pi[s] the action in state s
    V = np.zeros(P.shape[0])
    for _ in range(sweeps):
        V_new = np.zeros_like(V)
        for s in range(P.shape[0]):
            a = pi[s]
            V_new[s] = np.sum(P[s, a] * (R[s, a] + gamma * V))
        V = V_new
    return V
```

Terminal cells have all-zero rows in `P`, so their value stays 0.

</details>

</Step>

<Step title="Exploration versus exploitation">

An agent that always repeats the best action it knows may never find a better one. It must sometimes try actions that look worse. To see this cleanly, strip the world down to a **bandit**: one state and five actions ("arms"), each paying a random reward around its own hidden average. The agent keeps an estimate of each arm's average, updated after every pull.

Three strategies compete. **Greedy** always pulls the arm with the best estimate. **ε-greedy** does that most of the time but pulls a random arm with probability ε. **UCB** adds a bonus to rarely tried arms, so uncertainty itself attracts pulls. The right-hand curves average 50 different bandits; the left bars show one run, with the true averages as ticks.

<BanditLab client:visible mode="explore" arms={5} epsilons="0,0.1" ucb={true} runs={50} steps={500} seed={7} title="Greedy, ε-greedy and UCB on 50 bandits" />

In the last 100 of 500 steps greedy picks the best arm 74% of the time, ε = 0.1 picks it 89% of the time and UCB 91%. The greedy gap is worse than it looks: in 13 of the 50 runs greedy ended up mostly pulling an arm that is not the best. An early unlucky pull on the best arm made it look bad, and greedy never looked at it again.

<details>
<summary>Show the math</summary>

The estimate after $N$ pulls updates incrementally, without storing the rewards:

$$Q_{N+1}(a) = Q_N(a) + \tfrac{1}{N+1}\bigl(r - Q_N(a)\bigr).$$

UCB pulls the arm with the largest $Q(a) + c\sqrt{\ln t / N(a)}$, where $t$ is the step and $N(a)$ the number of pulls of arm $a$. The bonus shrinks as an arm is tried. Here $c = 2$.

</details>

</Step>

<Step title="Rewards shape behaviour">

The reward is the only thing the agent is told, so changing it, even slightly, can change everything the agent does. On our grid the only knob is the reward for each move. The figure finds the best policy for every value of it, from −2 to +0.1, and spends the same time in each stretch where the best moves stay unchanged. Drag the timeline to move through them.

<GridWorldLab client:visible mode="optimal-policy" title="The best moves as the cost of a move changes" />

At the far left, each move costs so much that the agent just wants the episode to end: two cells, (4,1) and (3,2), walk straight into the pit. That stops for (3,2) once the reward is above −1.65, and for (4,1) above −0.453; from then on no cell steps into the pit. Around the usual −0.04 the best moves change four times within a narrow band, from −0.085 to −0.022, each time one near-tie cell turning around (the textbook's figure shows the changes at −0.085 and −0.022; the others are finer than it draws). At the right end something new happens: once each move pays more than about +0.0101 (with γ = 0.99), the best plan is never to finish, and even (3,3) turns away from the goal. A positive reward per move is a reason to stay alive. This is a small taste of **reward design**, and of how an agent can exploit a reward that does not mean what its designers meant. <Step title="Common misconceptions">

- **You might think** the reward tells the agent what to do. **Actually** it only scores what happened. The agent must work out which of its earlier actions led to the score, which is called credit assignment.
- **You might think** grabbing the biggest immediate reward is enough. **Actually** the return counts everything that follows. The best first move can be a costly one.
- **You might think** exploring is wasted effort. **Actually** without it, estimates of untried actions never improve: greedy got stuck on a worse arm in 13 of 50 runs.
- **You might think** value and reward are the same thing. **Actually** reward is one number from one move, and value is the expected return from a state under a policy.
- **You might think** discounting is only a mathematical trick to keep sums finite. **Actually** it expresses how much the future matters, and it changes the best policy, as the discount figure showed.

</Step>

<details>
<summary>Why does the Markov property make value functions possible?</summary>

If the next state depended on the whole history, a state would not have a single value: it would depend on how the agent arrived. Because the present state is enough, one number per state summarises the future.

</details>

<details>
<summary>In the slippery grid, why can V(s) be lower than the reward of the shortest path?</summary>

The shortest path assumes every move goes as asked. Slips cost extra moves, and sometimes push the agent toward the pit. The value averages over all of that.

</details>

<details>
<summary>A greedy bandit agent's first pull of the best arm happened to pay badly. What happens next, and why does ε fix it?</summary>

Greedy now thinks that arm is poor and pulls another one. Nothing new ever corrects the bad estimate. With ε > 0 the agent sometimes pulls the arm again at random, and the estimate drifts toward its true average.

</details>

<details>
<summary>What policy would you expect with a reward of +0.5 for every move and γ = 1?</summary>

The agent would avoid both exits and wander forever, since each move pays and ending the episode stops the payments. With γ = 1 the total grows without bound, which is why the figure uses γ = 0.99 for positive rewards.

</details>

</Step>

<Step title="Twenty questions, asked of data">

A decision tree plays twenty questions with your data. It asks a yes/no question about one measurement ("is $x$ at most 0.56?"), sends each point down the yes or no branch, and repeats the game inside each branch until it is ready to guess a class.

In the figure, every point has two measurements, $x$ and $y$. Circles are class 1 and diamonds are class 0. There are 70 points: 47 of class 0 and 23 of class 1. Watch the coloured line slide across. It is a **threshold**, one candidate question, and the points to its left would answer yes. The curve below records how mixed the two resulting groups are on average, for every position. The lowest point of the curve wins, the threshold snaps back to it, and it becomes the first box of the flowchart on the right.

</Step>

<Step title="Impurity: how mixed is a node?">

To compare questions we need a number for "how mixed is this group?". A group that is all one class is **pure**: guessing that class is never wrong. A group split half and half is as uncertain as it gets. Write $p$ for the fraction of class 1 in a node. Two standard scores:

$$\text{Gini} = 1 - p^2 - (1-p)^2 = 2p(1-p), \qquad \text{entropy} = -p\log_2 p - (1-p)\log_2(1-p).$$

Both are zero when $p = 0$ or $p = 1$, and both peak at $p = 0.5$: Gini at 0.5 and entropy at 1 bit. Watch $p$ run from 0 to 1 while the dots flip class one at a time, or drag $p$ yourself. The dashed curve is entropy divided by two. It lies close to the Gini curve, which is why the two scores almost always choose the same split in practice.

<TreeSplitter client:visible mode="impurity" title="Gini and entropy against the class mix" />

<details>
<summary>Show the math</summary>

For classes with fractions $p_1, \dots, p_K$, Gini is $1 - \sum_k p_k^2$ and entropy is $-\sum_k p_k \log_2 p_k$. With $p = 0.3$ (30 dots of class 1 in the figure): Gini $= 2 \cdot 0.3 \cdot 0.7 = 0.42$ and entropy $= -0.3\log_2 0.3 - 0.7\log_2 0.7 \approx 0.881$ bits. Near $p = 0.5$ entropy is about twice Gini, which is why the dashed curve hugs the solid Gini curve.

</details>

</Step>

<Step title="Information gain: pick the split that removes the most mixing">

A split sends $n_L$ points left and $n_R$ right. The children are smaller groups, each with its own impurity $I$, so we average them weighted by size:

$$\text{gain} = I(\text{parent}) - \left( \frac{n_L}{n} I(\text{left}) + \frac{n_R}{n} I(\text{right}) \right).$$

This drop in impurity is the **information gain**. With entropy as $I$ it is literally the information gained; with Gini it is the same idea. The tree is greedy: it tries every threshold on every feature and keeps the one with the largest gain.

In the first figure the parent node (all 70 points) has Gini 0.441. The best threshold on $x$ is $x \le 0.56$. It produces a left child of 34 points (32 of class 0, 2 of class 1, Gini 0.111) and a right child of 36 points (15 of class 0, 21 of class 1, Gini 0.486). The weighted average is 0.304, so the gain is $0.441 - 0.304 = 0.137$. In the figure below, both features sweep at once and the curves show the gain. The best threshold on $x$ reaches 0.137 and the best on $y$ only 0.084, so $x$ wins and the $y$ line fades. Switch the impurity to entropy: the numbers change (the root gain becomes 0.253) but the winner does not.

<TreeSplitter client:visible mode="gain" title="Two features compete: the larger gain wins" />

<details>
<summary>Show the math</summary>

Why weight by size? The expected impurity after the split is what a point sees on average: with probability $n_L/n$ it lands in the left child, with probability $n_R/n$ in the right. A split that peels off one lone point leaves the big child almost unchanged, so its gain is tiny.

</details>

<details>
<summary>Show the code</summary>

```python
import numpy as np

def gini(y):
    p = np.bincount(y, minlength=2) / len(y)
    return 1 - np.sum(p ** 2)

def best_split(X, y):
    best = (0.0, None, None)                     # gain, feature, threshold
    parent = gini(y)
    for j in range(X.shape[1]):
        xs = np.unique(X[:, j])
        for thr in (xs[:-1] + xs[1:]) / 2:       # midpoints between neighbours
            left = X[:, j] <= thr
            w = left.mean()
            gain = parent - (w * gini(y[left]) + (1 - w) * gini(y[~left]))
            if gain > best[0]:
                best = (gain, j, thr)
    return best
```

</details>

</Step>

<Step title="Recursion: grow the whole tree">

Once a node is split, each child is its own small problem with fewer points. The tree applies the same procedure to each one: sweep, pick the best threshold, split. It stops when a node is pure, when it reaches the depth limit, or when no split helps. The resulting regions are **axis-aligned rectangles**, and the flowchart on the right describes exactly those rectangles: the upper branch is the yes answer, and each box shows its number of points and its impurity.

Watch the tree grow from the root. At the second level the right node (36 points, Gini 0.486) is the most mixed, and splitting it on $y \le 0.59$ gains 0.247. That is nearly twice the root's gain, and it leaves children of 22 points (19 of class 1) and 14 points (12 of class 0). The finished tree has 7 leaves and classifies 91% of the training points correctly. To keep the demo readable, leaves must hold at least 3 points, so it does not spend a split on one stray point. Use the menus to change the impurity or the maximum depth. Entropy grows exactly the same tree here.

<TreeSplitter client:visible mode="grow" title="Growing a tree, one split at a time" />

<details>
<summary>Show the code</summary>

```python
def grow(X, y, depth, max_depth):
    gain, j, thr = best_split(X, y)
    if depth == max_depth or gain <= 0:
        return {"class": np.bincount(y).argmax()}
    left = X[:, j] <= thr
    return {"feature": j, "threshold": thr,
            "yes": grow(X[left], y[left], depth + 1, max_depth),
            "no": grow(X[~left], y[~left], depth + 1, max_depth)}
```

</details>

</Step>

<Step title="Depth, pruning and overfitting">

A tree can keep splitting until every training point sits in a pure leaf. That tree gets every training answer right, including the mislabelled ones. Here 12% of the labels were flipped at random, so the true pattern (class 1 is the lower-right rectangle) is hidden behind noise.

Drag the **max depth** slider, or watch the timeline. The training accuracy climbs from 67% at depth 0 to 100% at depth 5 and never comes down. **Validation accuracy** is measured on 600 fresh points the tree never saw. It peaks at depth 2 (84%) and then falls to 76%, because the deeper splits carve tiny boxes around noisy points and those boxes do not generalise. By depth 8 the tree has 12 leaves and the gap between the two curves is 24 points. That gap is overfitting.

Stopping early is called **pruning**. Limiting the depth is one way; demanding a minimum number of points per leaf is another. Set **Min points per leaf** to 6: the tree can no longer make tiny boxes, training accuracy stays at 90%, and validation accuracy holds at 85% at every depth from 2 onwards. A second style, post-pruning, grows the full tree first and then cuts back branches that do not pay for their complexity.

</Step>

<Step title="Common misconceptions">

- **You might think** a deeper tree is a better tree. **Actually** training accuracy only rises with depth, but validation accuracy peaks and then falls once the tree starts fitting noise.
- **You might think** Gini and entropy lead to very different trees. **Actually** their curves have almost the same shape, and they usually pick the same splits.
- **You might think** a tree can draw slanted or curved boundaries. **Actually** every split is one threshold on one feature, so the regions are axis-aligned rectangles. A diagonal boundary needs many small steps.
- **You might think** the greedy choice at the root gives the best possible tree. **Actually** each split is chosen only for its immediate gain, and the tree never goes back to reconsider.

</Step>

<details>
<summary>A node holds 10 points, all of class 1. What are its Gini and entropy?</summary>

Both are 0. A pure node has nothing left to sort out.

</details>

<details>
<summary>A node is split half and half between two classes. What is its Gini impurity?</summary>

$1 - 0.5^2 - 0.5^2 = 0.5$, the maximum for two classes. Its entropy is 1 bit.

</details>

<details>
<summary>A split sends 10 points left (Gini 0.2) and 30 points right (Gini 0.4) from a parent with Gini 0.45. What is the gain?</summary>

The weighted child impurity is $\tfrac{10}{40}\cdot 0.2 + \tfrac{30}{40}\cdot 0.4 = 0.35$, so the gain is $0.45 - 0.35 = 0.10$.

</details>

<details>
<summary>Training accuracy is 100% but validation accuracy is 76%. What is going on and what can you try?</summary>

The tree has memorised the training set, noise included. Limit the depth, require more points per leaf, or prune branches afterwards.

</details>
